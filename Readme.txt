Согласно заданию, имеется некий сервер, принимающий запросы по протоколу HTTP.
Первая dll SmartMealOrder.Http.

Вторая dll работает по gRPC: SmartMealOrder.Grpc.

Обе dll реализуют IMealServiceClient, определенную SmartMealOrder.Core.

Консольное приложение должно подключить dll, созданную ранее. Сервер принимает запросы по протоколу HTTP, поэтому рабочим вариантом будет подключение SmartMealOrder.Http, так как SmartMealOrder.Grpc не сможет работать с этим сервером (HTTP).

Консольное приложение может подключить обе dll и переключать транспорт (HTTP/gRPC). Это позволит использовать dll SmartMealOrder.Grpc, если будет gRPC сервер.
Выбор транспорта реализован через appsettings.json. Это позволяет выполнять гибкое переключение:
  "ClientSettings": {
    "Transport": "Http"
  },

Таким образом, используется соответствующая реализация ImealServiceClient.

Настройки логина и пароля (HTTP) также находятся в appsettings.json:
  "HttpClient": {
    "BaseUrl": "http://localhost:6001/Meal",
    "Username": "admin",
    "Password": "admin123"
  },

Для тестового запуска необходимо запустить моковые сервера и консольное приложение.



Задание 2

Использование ReactiveUI я привёл в качестве примера. Для данной ViewModel это может выглядеть избыточным, но в реальном проекте такой подход полностью себя оправдывает при усложнении логики.
Например, ReactiveUI незаменим, когда нужно отслеживать изменения сразу нескольких свойств, объединять их в цепочки и выполнять реактивные вычисления.
Кроме того, фреймворк даёт ещё ряд важных преимуществ:
•	Удобная работа с асинхронностью и командами (ReactiveCommand): из коробки поддерживается управление состоянием загрузки (IsExecuting), обработка ошибок и автоматическое управление доступностью команды (CanExecute).
•	Фильтрация и троттлинг событий: можно легко ограничить частоту вызовов (например, с помощью Throttle или DistinctUntilChanged), что крайне полезно при реализации «живого» поиска или ввода данных.
•	Декларативный биндинг: реактивный биндинг делает код более читаемым, избавляет от громоздкой подписки/отписки на события и упрощает покрытие ViewModel юнит-тестами.
